# Measurements

Peter, 2026-11-10: every data finding is recorded here, with its status (complete or partial), the data it covers
(pointers), the code that produced it, and whether an LLM was involved. This is the quantitative record; the
qualitative interpretations live in `docs/OBSERVATIONS.md` (O-numbers) and risks in `docs/RISK-REGISTER.md`
(R-numbers). Raw data stays on the box (no data in git); these files point to it.

## How to read an entry

Each `M<nn>-*.md` file answers:

- **What was measured**: the metric, its unit and the population.
- **What was observed**: the numbers.
- **How**: the run command, the code, and every LLM in the loop. An LLM can enter in three ways, labelled in each
  entry:
  - **policy**: the model under test (Granite 4.2 8B or GPT-6 Luna).
  - **judge**: an LLM used inside the measurement itself, e.g. the Jev option judge that maps a free-text verdict onto
    the answer key.
  - **Claude-read**: numbers or labels that Claude (the coding agent) produced by reading replies or traces, or by an
    ad-hoc query that was not saved as a script. These are less reproducible and are marked as such.
- **Status**:
  - `COMPLETE`: every scheduled sample is in.
  - `PARTIAL`: the run is still going or was stopped; the entry says how far it got and when.
  - `ABORTED`: stopped and archived; kept for the record, not for conclusions.
  - `SUPERSEDED`: complete, but its inputs (e.g. traces) have since changed.

## Datasets, the run registry and the tensor

- **Datasets.** `datasets/<name>.md` (readable) and `datasets/<name>.manifest.json` (every scenario, trace and served
  case file, with sha256 prefixes) describe exactly which scenarios, traces, cases and answer keys an eval uses, and how
  they were selected. Generated by `code/eval/analysis/dataset_manifest.py`. Pilot 2 (M06, M07, M09, M11):
  [datasets/pilot2.md](datasets/pilot2.md).
- **Run registry.** [runs.yaml](runs.yaml): one entry per run directory, i.e. per condition, with its factor values
  (policy, scaffold, thinking, ...). Register a run before launching it.
- **Tensor.** `code/eval/analysis/tensor.py build` turns every registered run into one table
  (`results/tensor/replies.parquet`, one row per reply: factors + arm/x1/x2/idx + outcomes). `view`, `contrast` and
  `standard` produce tables with family-bootstrap CIs and paired per-X1 contrasts. Generated views go in `views/`.

## Shared method: the transfer pilots (M01, M03, M05-M09)

- **Question.** Does a case from another domain with the same considerations (K) help an agent decide a live
  scenario (X1), and does the agent reason from the case or copy its verdict?
- **Arms** (one per cell, X1 fixed):
  - `control`: no case.
  - `self`: X1's own case.
  - `transfer`: a cross-domain sister with the same K.
  - `flip`: that sister with 1-2 facts changed so one of its own flip conditions holds and its verdict differs from
    X1's gold.
  - `decoy`: another anchor's sister (different K).
- **Answer key.** Every arm is scored against X1's own gold verdict.
- **Cells.** The sisters were written by `code/pipeline/transfer/build.py`:
  - The sister and flip writer is GPT-6 Luna on Bedrock (role `transfer_writer`, temperature 0.4).
  - A blind-solve check is GPT-6 Luna (role `transfer_checker`, temperature 0).
  - Prompts are in `code/pipeline/transfer/prompts/`; the flip prompt is `flip.v1.md`.
  - Builds:
    - Pilot 1: `results/transfer/build-pilot-20261109.jsonl`, review sheet `results/transfer/PILOT-SISTERS-2026-11-09.md`.
    - Pilot 2: `results/transfer/build-batch2-20261109.jsonl`, `results/transfer/BATCH2-SISTERS-2026-11-09.md`.
  - The cell list per run is in `<run>/cells.json` and in `config.json`.
- **Traces.** X1's trace comes from the trace store `data/store/traces/<X1>/trace.json`.
  - Renderer: GPT-6 Luna (role `renderer`, temperature 0.7), prompt `code/pipeline/render/prompts/render.v*.md`.
  - Gates (all LLM: GPT-6 Luna role `answer_leak_checker`, temperature 0): answer-leak (`pipeline.render.answer_leak`)
    and framing (`pipeline.render.framing_check`).
  - Each entry says which render version its traces were.
  - Older trace versions are under `data/store/traces/_versions/`.
- **Policy run.** `code/eval/allpairs.py run --cells ...`; settings are frozen in `<run>/config.json` at first launch.
  - Prompt: harness equities `pilot2` + the full case card + `analogical.v1.md` + `format.v1.md`.
  - Granite: Granite 4.2 8B, bf16, local vLLM (role `policy`, temperature 1.0).
  - Luna: GPT-6 Luna on Bedrock (role `policy_luna`, reasoning effort medium, provider-default temperature, no prefill,
    a start instruction instead; `API_START` in allpairs.py).
  - Reasoning modes:
    - C: the YAML steps are written inside `<think>`, with the prefill `kind: fact_enumeration`.
    - A: free prose thinking, then the YAML.
  - k replies per cell; the schedule runs sample-major, so a partial run covers every cell evenly.
- **Scoring** (`allpairs-scoring-v3`, in each sample's `scoring` field):
  - The reply is parsed deterministically (`bench.schema.parse_reply`, with format repairs, recorded in
    `format_repairs`).
  - The verdict's option is mapped to X1's options by the **Jev Choice judge**: an LLM, `openrouter/typesafe/jev-1.14`,
    temperature 0, cached in `results/judge_cache.sqlite`, threshold 0.5.
  - No mapping means `off_menu` (scored wrong). `correct` = mapped option == X1's gold.
- **Report.** `code/eval/transfer_report.py --run <run>` writes `<run>/report.md`. It is deterministic given the
  samples.
  - Accuracy is the mean over X1 of per-X1 accuracy, with a 95% family-bootstrap CI (2,000 resamples over scenario
    families).
  - **Copy rate**: the share of replies whose mapped choice equals the served case's verdict, mapped back to X1's
    option ids through the sister's `lineage.detail.option_permutation`.
- **Cross-run comparison and flip mechanics.** `code/eval/analysis/mode_compare.py` (deterministic; M08, M09).

## Data validity notes

- **Pilot 2 runs saw identical traces.** All 28 pilot-2 X1 traces were last written 2026-11-09 22:24-22:26 UTC
  (render.v5, rerender log `results/render/rerender-v5b-20261109.jsonl`). That is before M06 (Luna) started at
  23:11, and nothing re-rendered them afterwards. So M06, M07 and M09 compare like with like.
- **Pilot 1 runs did not all see the same traces.** M01 and M03 ran on render.v3 traces. The 10 pilot-1 X1 traces were
  re-rendered (v4, then v5) by 22:18 UTC on 2026-11-09, before the M05 runs. M01/M03 are therefore not comparable with
  M05; that difference is what M05 measures.
- **Luna cost was estimated, not metered.** About $0.002 per Luna policy call, from `config/prices.yaml` list prices
  (OpenRouter's; Bedrock's price is unconfirmed). The cost ledger `results/costs.json` was last regenerated
  2026-10-28 and does not cover these runs.
