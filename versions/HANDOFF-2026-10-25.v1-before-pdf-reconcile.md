### 1. Eval set from what exists (≤1 hr)
- Scenarios with rendered traces: B001's 12 lives + AUT-101, INT-103-v01, AGT-201-v01 (≈15). Each live has its
  reference card, an `-r1` revised card (for some), and decoy card(s) listed in `decoys:`.
- Build a loader → Inspect `Sample`s: input = `trace.json` messages; metadata = live id, case id, variant, gold
  (choice, acceptable, option signatures, irreversible flags, relation), and the served card for each arm.
- Arms (solvers): `no-card` (trace with the final harness message removed), `card-plain`, `card-structured`,
  `revised-card` (serve `-r1`; gold becomes the revised card's answer — this is the counterfactual "case swap"
  test: does the action follow the card it was served?), `decoy` (serve a decoy; gold choice unchanged).
- Cards rendered with `mvp.py card <reference.yaml>` (and `--spine` for the prose ablation later).
- Tools: the trace's tool list. The model's tool calls are recorded, **not executed**; one assistant turn per
  sample. Tool calls come back structured from vLLM, or parse Hermes `<tool_call>` blocks
  (`reward_v2.parse_completion` handles both).

### 2. Scorer (≤1 hr)
- Primary: **action** — match the calls to a live option with `reward_v2.match` / `analyze_calls` against
  the hidden signatures in the live file; right / wrong / wrong-and-irreversible / no match. Note the live
  files' gold uses `signature: {calls, without}` per option plus `irreversible` — same semantics as reward_v2.
- Log: matched option, n_calls, extra calls, irreversible call, hand-up rate (move ask/partial), and for
  `card-structured` whether the reply's relation matches gold (parse leniently; untrained models will be messy).
- Report with case-clustered bootstrap CIs (whole case families resampled), per arm and per variant.

### 3. Run the pilot, then plot (≤1 hr)
