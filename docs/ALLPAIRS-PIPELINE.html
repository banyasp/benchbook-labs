What the base model sees

Control: G(T)

  1. System prompt of the trace (the agent's role and tools).
  2. The trace, flattened into one user message.
  3. Harness injection: the 34 equities of pilot2, then the no-reference format spec (format.v1-noref.md): fact_enumeration → consideration_enumeration → reasoning → verdict.
  4. Prefill <think> kind: fact_enumeration, so the reply starts with the facts.

With the case: G(T, C)

  1. Same system prompt and trace.
  2. Injection: the equities, the case card C(X2) (setting, decider, situation, question, options, facts, considerations, reasoning, verdict, flip conditions, lesson, limits), the analogical-method text (analogical.v1.md), then the full format (format.v1.md), which adds fact_mapping, consideration_mapping and applicability.
  3. Same prefill.

About 14,000 characters for a control prompt and 27,000 with a case. Read both in full in results/allpairs/prompt-examples/ (one Cuban Missile Crisis X1 with another Cuban Missile Crisis decision as the case).

dist(G, A): the whiteboard rows as built

RowWhiteboardImplementation (score name in samples.jsonl)
V · primaryExact_Match(translate(VG), VA)correct: the model's chosen option is translated through the option alignment (or its text aligned directly) and matched to the key's choice. Unalignable = off-menu, scored wrong. No verdict (e.g. cut off at 12,000 tokens) = wrong.
FENUM_GRADER(FG, FA)facts_enum (+ found, conflated, absent, extraneous, duplicate counts). Facts behind decisive considerations weigh 2.
QJev_Noul & ENUM(QG, QA)frame_question, frame_decider, frame_role (Jev_Noul, 0–1) and options_enum (ENUM over the option alignment).
KENUM(translate(KG), KA)considerations_enum: ENUM over the consideration alignment; for each aligned pair, the cited facts (translated through the fact alignment) and favored options (translated through the option alignment) are set-compared, and equity and weight exact-matched.
W—Stored in raw/ for qualitative reading; not scored.
Mnot in evalWritten by the case model only; not scored (no gold mapping for arbitrary pairs).

Alignment (the translator and the mapper): Jev Choice asks, for every gold item, which generated item it is, and for every generated item, which gold item it is; the two answers are combined (geometric mean), and pairs are taken greedily above the threshold. That gives each generated id its answer-key id, in any order the model wrote them.
